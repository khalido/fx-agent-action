- 2026-10-12: cost.sh's old exit-on-spend defect is closed (0742d09, 2026-09-29); it prices per generation but still sums both bases into one `cost=`, and `providers=` names only the BYOK side. Measured here: cost.sh printed `cost=0.006271264 providers=deepseek` while $0.002354 of it was gateway-billed gpt-5.6-luna helper calls. #11's remainder is the cache split plus `cost_gateway=`/`cost_upstream=`, not a symbol on the total — a run mixing a gateway-billed helper with a BYOK main model is normal here. Cache reads are not a rounding error: on the gateway catalog deepseek/deepseek-v4.1-flash cache read is 2.3% of its input price (gpt-5.6-luna 10%), so `in` alone never predicts cost. Tokens come from steps.run while dollars prefer steps.memory_save (post-compaction), so the two cover different requests; folding the token totals into cost.sh's late read fixes both. post-comment's `cents` rounds to 0.1¢, so split parts of a sub-cent total can print larger than their sum.
- 2026-10-13: An fx run on this repo cannot ship a change to action.yml or scripts/. The integrity step reverts them and warns only when `.agent-pr.md` is absent; with it present the step fails the run, and the session, memory_save and comment steps are all gated on `steps.integrity.outcome` (the pr step on `== 'success'`), so you lose the comment too. Write the change up as a note for a person instead.
- 2026-10-05: memory.sh's 409 merge uses `git merge-file -p --union`, which exits 0 on a content conflict (git 2.55; plain merge-file exits 1), so the conflict-then-lost path in #10 is closed for content. Both merges compare `file` against `before.md` and `theirs`; compaction rewrites `file` but not `before.md`, so a 409 after a compaction merges a rewritten side against a stale base — union keeps both, no loss, but a shrink is partly undone. The remaining dropped-run path is the one-shot retry: api_get failing or a third writer 409ing the retry PUT loses the run at the final warning. check.yml still tests none of memory.sh.
- 2026-10-12: #24 cannot be built on `actions/cache`. GitHub lets only push, workflow_dispatch, repository_dispatch, delete, registry_package, page_build and schedule write a cache in the default branch's scope; `issues` and `issue_comment` are read-only there, and a save on them is skipped with a log warning while the step and job stay green. So a session cache would populate in the `workflow_dispatch` runs used to test it and never in production — the same shape as the `pr` verb that shipped broken. The only opt-out is `cache-mode: write` in the consuming workflow, which a composite action cannot set, and it is a documented cache-poisoning trade on the one trigger outsiders can influence. The same rule is why the fx-binary cache was dropped (#26, 2026-10-13): it only ever populated on a dispatch run, so every issue/comment run missed and logged a "Failed to save" warning for a download that takes half a second. No actions/cache step is left in action.yml, and the prose that promised a cached binary (AGENTS.md, docs/guide.md, examples/minimal-no-action.yml) went with it in 8728b61. Also caches are immutable per key, so the session id (stable across resumes) cannot be the key: the second save is skipped and every later run resumes run 1. Branch scope still bites too — a `pull_request` run saves on the merge ref, invisible to the default-branch `issue_comment` run on the same PR — and a write gate would have to sit on the save step, since a read-mode run still writes a session.
